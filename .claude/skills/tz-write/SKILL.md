# 第N話の本文（初稿）を書く

引数：$ARGUMENTS（話数）

1. **前提を確かめる**：`episodes/第0部/NN_*/骨組み.md` があり、状態が「オーナー承認」であること。違えば `/tz-plan N` を案内して止まる。すでに `本文.md` があるなら、上書きせずに `/tz-round N` を案内する（初稿をやり直したいとオーナーが言った場合だけ、現在の `本文.md` を `履歴/本文_r0_破棄_日付.md` に退避してから進める）。

2. **書かせる**：`tz-writer` を呼ぶ。渡すもの：話のフォルダのパス、「初稿」であること、前の話の本文のパス。

   **第0話だけ、その前に視点の A/B を行う**（決定ログ 2026-10-12。`AB/` フォルダがまだない時）：
   - `tz-writer` を2回 **同時に** 呼び、骨組みのシーン1（1,500字前後）を、一人称版（`AB/A_一人称.md`）と三人称版（`AB/B_三人称.md`）で書かせる。どちらも同じ骨組み・同じ事実で書く。
   - 両方を `python3 harness/tools/measure.py --compare` で測る（三人称版は比較のため視点の印を付けずに測る）。
   - オーナーに両方のパスと数値の比較を見せ、読み比べてもらう。気づいたこと（一人称で効いた所、失ったもの、配分の感触）を `AB/所感.md` に原文のまま残し、`/tz-decide` で `harness/文体/本作の文体.md`「視点」に反映する。
   - 一人称で書くこと自体は決定済み。A/B は書き方と配分の調整に使う。オーナーが方針を変えると言った時だけ、`/tz-decide` で決定を覆す。

3. **整合チェック**：`tz-continuity` を呼び、結果をそのまま話のフォルダの `整合.md` に保存する。

4. **要修正があれば一度だけ直す**：「要修正」がある場合、その一覧を `tz-writer` に渡して、該当箇所だけ直させる（全体を書き直させない）。その後もう一度 `tz-continuity` を呼び、`整合.md` を更新する。それでも残る指摘は、そのままオーナーに見せる。

5. **初稿を退避する**：`本文.md` を `履歴/本文_r0.md` にコピーする（以後の比較用）。

6. **進行表を更新する**：`episodes/第0部/進行表.md` の該当行を「初稿」にし、字数（measure.py の値）を書く。

7. **オーナーに見せる**：
   - 本文のパスと、measure.py の数値（字数、孫の手:三嶋 の配合推定、✕ の指標、骨組みの配合とずれた場面）
   - 執筆担当の自己評価（効いている所／弱い所）
   - 整合チェックの「要決定」「canon 化の候補」
   - 次の一手：本文を読んでもらい、`/tz-round N` で三嶋・孫の手の提案に進む

本文の全文はチャットに貼らない（長いので、ファイルで読んでもらう）。
